# ระบบพัฒนาโครงงาน (SDU Task Tracker) v2.3

ติดตาม มอบหมาย ส่ง และตรวจสอบโครงงาน — Express + Handlebars + Passport · ข้อมูล/บัญชี/ไฟล์เก็บใน **Supabase** · รันบน **Vercel**
ไฟล์ทั้งหมดอยู่ที่ **รากของรีโป** (ไม่มีโฟลเดอร์ซ้อน) push ขึ้น GitHub แล้ว Import เข้า Vercel ได้ตรงๆ

## ติดตั้งบน Vercel + Supabase (ทำตามลำดับ)
**1) Supabase** — โปรเจกต์ `teinpwonkkexdjykqnuy` รัน migration ไว้แล้ว (ตาราง `app_records`, `app_sessions`, ฟังก์ชัน `app_apply`, bucket `submissions`, RLS เปิด) ถ้าสร้างโปรเจกต์ใหม่ ให้เปิด SQL Editor รันไฟล์ใน `supabase/migrations/` ตามลำดับชื่อ
**2) Vercel** — Add New → Project → เลือก repo นี้
- Framework Preset: **Express** (ตรวจพบอัตโนมัติ) · Root Directory: **ว่าง** (รากของรีโป) · Build/Install/Output Command: **ปล่อยว่าง ไม่ Override**
- Settings → Environment Variables (Production) ใส่ตาม `.env.example`: `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `SESSION_SECRET`, `CRON_SECRET` และแนะนำ `ADMIN_PASSWORD`, `ADMIN_EMAIL`
- `SUPABASE_SECRET_KEY` = Supabase → Project Settings → API Keys → **Secret key** (`sb_secret_…`) — ห้ามเผยแพร่ ห้าม commit **ไม่ใช่ publishable key** (ระบบนี้เข้าฐานข้อมูลจากฝั่งเซิร์ฟเวอร์เท่านั้น ตารางทั้งหมดปิด anon/authenticated ด้วย RLS)
**3) Deploy** แล้วเปิด `https://<โดเมนของคุณ>/healthz` ต้องได้ `"ok": true` และ `"db": "ok"` ถ้า `ok` เป็น false จะบอกว่าขาดตัวแปรใดหรือต่อ Supabase ไม่ได้
**4)** เข้าสู่ระบบด้วยบัญชี Admin → เปลี่ยนรหัสผ่านที่ชื่อมุมขวาบน

### ถ้า deploy มีปัญหา
| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| `pattern "api/index.js" defined in functions doesn't match…` | ต้องไม่มีโฟลเดอร์ `api/` และไม่มี `functions`/`rewrites` ใน `vercel.json` (รุ่นนี้ไม่มีแล้ว) |
| หน้าขึ้น "ยังตั้งค่าบน Vercel ไม่ครบ" | เพิ่มตัวแปรที่ระบุ แล้ว Redeploy (Environment Variables มีผลกับ deploy ใหม่เท่านั้น) |
| 404 ทุกหน้า / หา entrypoint ไม่เจอ | Root Directory ต้องว่าง และ `package.json` อยู่ที่รากรีโป (ไม่ใช่ในโฟลเดอร์ย่อย) |
| `Failed to lookup view` | ไฟล์ `views/` ไม่ถูกรวมเข้าฟังก์ชัน — ตรวจว่า `lib/trace.js` อยู่ครบ รัน `npm test` (มีเทสต์ตรวจ) |
| `/healthz` → `db: error 401/403` | `SUPABASE_SECRET_KEY` ผิดหรือเป็น publishable key |
| `/healthz` → `db: error 404` | ยังไม่ได้รัน migration |

## บัญชีและการเป็นผู้ดูแลระบบ
- เปิดเว็บครั้งแรก ระบบสร้างบัญชี **Admin** (รหัสผ่านตั้งต้น `tiansmith735` หรือค่า `ADMIN_PASSWORD`) — ไม่ใช้ "ผู้ใช้คนแรก" เป็นผู้ดูแล ชื่อ `admin` สมัครเองไม่ได้
- **อีเมลจริงของผู้ดูแล:** ตั้ง `ADMIN_EMAIL` แล้ว Redeploy → ล็อกอินด้วยอีเมลนั้นหรือชื่อ Admin ก็ได้ คนอื่นสมัครด้วยอีเมลนี้ไม่ได้เพราะถูกใช้แล้ว
- **รหัสตั้งต้นอยู่ในโค้ดบน GitHub** ใครเปิดดูก็เห็น: ตั้ง `ADMIN_PASSWORD` ก่อน deploy ครั้งแรก (ใช้ตอนสร้างบัญชีครั้งแรกเท่านั้น หลังจากนั้นเปลี่ยนที่ "บัญชีของฉัน") ระบบมีแถบเตือนสีแดงจนกว่าจะเปลี่ยน
- **แต่งตั้งผู้ดูแลคนอื่น:** เมนู "ผู้ใช้" → ช่องบทบาท → "ผู้ดูแลระบบ" (มีข้อความยืนยัน) · บัญชี Admin หลักและบัญชีของตัวเองลบ/ลดสิทธิ์จากหน้านี้ไม่ได้
- **อาจารย์:** ผู้สมัครติ๊ก "ขอสิทธิ์อาจารย์" แล้วผู้ดูแลกด "อนุมัติ"
- ล็อกอินด้วย **ชื่อผู้ใช้หรืออีเมล** ได้ · **ลืมรหัสผ่าน:** ถ้าตั้ง `SMTP_URL` + `BASE_URL` ระบบส่งลิงก์ตั้งรหัสใหม่ทางอีเมล (ใช้ได้ 1 ชั่วโมง) ไม่เช่นนั้นให้ผู้ดูแลกด "รีเซ็ตรหัสผ่าน" · อีเมลไม่มีการยืนยันตอนสมัคร (ผู้ดูแลตรวจได้จากเมนู "ผู้ใช้")

## ผู้ใช้ 3 ประเภท
| บทบาท | ทำได้ |
|---|---|
| **บุคคลทั่วไป** | กรอกโครงงาน (เลือกอาจารย์/สมาชิกจากบัญชีในระบบ หรือพิมพ์เอง) · **ส่งงานให้อาจารย์** เป็นลิงก์/ไฟล์จากหน้าแรกหรือหน้าโครงงาน · รับทราบ/ส่งงานที่ได้รับมอบหมาย · ปฏิทิน · พูดคุยในโครงงาน |
| **อาจารย์** | เห็นโครงงานที่เลือกตนเป็นอาจารย์ · มอบหมายงานให้บุคคลโดยตรง (ไม่ต้องมีโครงงาน) และ/หรือทีม · ตั้งวันเริ่ม/ส่ง/เวลานับถอยหลังตรวจ · ตรวจผ่าน/ตีกลับ (ต้องมีเหตุผล) · ตารางเวลา |
| **ผู้ดูแลระบบ** | เห็นทุกโครงงาน · จัดการ/ลบผู้ใช้ แต่งตั้งผู้ดูแล · ให้คะแนน (เห็นเฉพาะผู้ดูแล) · ล้างข้อมูลตกค้าง |

อาจารย์จะเห็นงานที่นักศึกษาส่งก็ต่อเมื่อ **บัญชีอาจารย์ผูกกับโครงงาน** — เลือกอาจารย์จากรายชื่อในระบบ (ระบบเตือนสีเหลืองถ้ายังไม่ผูก)

## การลบข้อมูล
ลบผู้ใช้ = ลบหมด: ถอดชื่อ/อีเมลออกจากรายชื่อทุกโครงงาน ลบงานรายบุคคลและแจ้งเตือนของเขา และเลือก "โอนโครงงานให้ฉัน" หรือ "ลบโครงงานด้วย" · เมนู "ผู้ใช้" มีแถบ "ล้างข้อมูลตกค้าง" สำหรับข้อมูลเก่าที่ค้างอยู่ · อีเมลเก็บเป็นตัวพิมพ์เล็กและเทียบแบบไม่สนตัวพิมพ์ (ฐานข้อมูลบังคับไม่ให้ชื่อผู้ใช้/อีเมลซ้ำ)

## โครงสร้าง
`src/index.js` จุดเข้าของ Vercel (ส่งออกแอปจาก `app.js`) · `db.js` ชั้นข้อมูล Supabase (โหลดต่อคำขอ บันทึกเฉพาะระเบียนที่เปลี่ยนด้วย `app_apply` แบบธุรกรรม + ตรวจ revision) · `lib/supa.js` ไคลเอนต์ PostgREST/Storage · `lib/sessionstore.js` เซสชันใน Supabase · `lib/files.js` ไฟล์ใน Storage (private) · `lib/trace.js` ช่วยให้ Vercel รวม views/public · `routes/` เส้นทาง · `views/` หน้าจอ · `supabase/migrations/` SQL · `tests/` ทดสอบด้วย Supabase จำลอง (`npm test`)

## รันในเครื่อง
```sh
npm install
npm test           # ทดสอบชั้นข้อมูล (ไม่ต้องต่อเน็ต)
npm start          # http://localhost:3000 — ถ้าไม่ตั้ง SUPABASE_* จะเก็บข้อมูลในไฟล์ data/db.json
```
ข้อจำกัด: ทุกคำขอโหลดข้อมูลทั้งตารางมาอ่าน เหมาะกับหน่วยงานเล็ก–กลาง · ไฟล์ส่งงาน 4 MB ต่อไฟล์บน Vercel ตามค่าตั้งต้น (`MAX_UPLOAD_MB`) · แผนฟรีของ Vercel ให้ Cron วันละครั้ง (แจ้งเตือนใกล้ครบกำหนด/อีเมลออกวันละรอบ) · ยังไม่มี CSRF protection และการจำกัดจำนวนครั้งล็อกอิน — ควรเพิ่มก่อนใช้งานจริง
